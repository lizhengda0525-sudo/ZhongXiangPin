# Harness 执行指南

本目录用于把旧版众享拼项目固化为新项目重构的 Harness。旧项目只作为只读行为参照，新项目才是唯一实现目标。

## 工作区边界

| 角色 | 路径 | 规则 |
| --- | --- | --- |
| 新项目 | `D:\JAVA\ZXP\zhongxiangpin` | 只在这里创建和修改代码、规格、测试、migration 和发布资料。 |
| 旧项目 Harness | `D:\ZXP\zhongxiangpin` | 只读。只查看业务行为、接口形态、数据结构、边界场景和测试证据，不复制源码。 |

## Harness 执行流程

每个实现任务按以下顺序推进：

1. 在 `docs/plan/06-task-implementation-checklist.md` 中确认任务编号。
2. 阅读 `docs/sdd/` 下对应的 SDD 文档。
3. 只打开 `docs/harness/reference-map.md` 中为该任务列出的旧项目文件。
4. 把提取到的行为写入任务说明或 PR 描述：正常流程、失败流程、隐性约束和测试证据。
5. 更新或确认 `docs/plan/openapi.yaml`、状态枚举、错误码和 migration 形态。
6. 只在新项目中实现。
7. 运行任务验证命令；如果暂时无法运行，要记录原因。
8. 在任务说明或 PR 描述中记录与旧项目或 SDD 的偏差。

## 从 Harness 提取什么

| 方面 | 应提取 | 不应提取 |
| --- | --- | --- |
| API | 方法、路径、请求响应字段、错误场景 | Controller 方法体源码 |
| 领域 | 状态流转、幂等键、不变量 | Service 类实现源码 |
| 数据 | 表职责、唯一键、状态字段 | 未经重设计直接复制 SQL |
| 前端 | 路由流程、页面状态、接口调用、校验行为 | Vue 组件源码 |
| 测试 | 关键断言、遗漏场景 | 测试代码直接复制 |

## 停止条件

出现以下情况时，先停止编码并更新 SDD：

- 旧项目行为与 OpenAPI 或新业务设计冲突。
- 任务需要的表、枚举或错误码尚未定义。
- 前端需要后端契约未暴露的字段。
- 高风险场景没有验证路径。
- 复制旧代码看起来比描述行为更省事；此时必须先描述行为。

## 与 SDD 的关系

Harness 回答“旧项目已经如何工作或失败”。SDD 回答“新项目要如何构建”。两者冲突时，要有意识地更新 SDD 并记录原因。
