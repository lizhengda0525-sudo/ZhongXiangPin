# 项目概览

## 项目定位

众享拼是一个面向电商拼团场景的重构项目。目标不是复制旧项目源码，而是在旧项目业务行为的基础上，用 Harness + SDD 的方式重新构建一个边界更清晰、契约更稳定、验证更充分的前后端一体系统。

## 重构目标

- 保留旧项目已跑通的 P0 拼团链路：登录、会场、试算、开团、参团、锁单、支付、退款、订单和后台治理。
- 强化交易可靠性：状态机、幂等键、Redis Lua 占位、MySQL 条件兜底、可靠事件和补偿任务。
- 强化工程边界：契约先行、领域与基础设施解耦、前后端类型对齐。
- 强化治理能力：活动、标签、订单、任务、DCC、线程池、审计和运行态指标。
- 强化交付证据：测试矩阵、CI、版本 tag、发布说明和回滚说明。

## 方法论

本项目采用 Harness + SDD：

- Harness：旧项目只作为可查询的行为参照，帮助提取业务流程、接口形态、隐性约束和测试证据。
- SDD：新项目以文档驱动实现，先定义契约、数据、状态、任务和验收，再进入编码。
- OpenAPI：作为前后端共享契约，避免字段漂移。
- migration：作为表结构、唯一键、状态持久化和 MySQL 交易事实源，先于后端持久化代码固定。
- 小步提交：每个任务只交付一个可验证增量。

## P0 主链路

```text
注册/登录 -> 多商品会场 -> 商品详情 -> 活动试算
-> 开团/参团 -> 锁单 -> Mock 支付 -> 订单查询
-> 退款/自动退款 -> 管理后台订单和任务治理
```

## 核心风险

- 身份风险：所有交易归属以后端登录态为准，前端传入的 `userId` 不可信。
- 金额风险：锁单前必须重新试算，订单必须保存价格快照。
- 并发风险：Redis 只是前置占位，MySQL 唯一键和条件更新是最终兜底。
- 幂等风险：锁单、支付、退款和任务执行使用不同幂等键。
- 任务风险：任务 handler 必须可重复执行。
- 缓存风险：后台活动变更必须触发版本失效或精确失效。
- 契约风险：OpenAPI 必须先于前后端并行开发完成。
- 阶段风险：M1/M2 只做契约和数据事实源，不提前写后端业务代码；M3 才开始后端工程骨架。

## 当前完成标准

当前阶段完成后，应具备：

- 文档入口清晰。
- Harness 参考路径明确。
- SDD 明确每个 Agent 的输入、输出和验收。
- OpenAPI 覆盖 P0 用户端、后端、管理端和运行态治理所需接口。
- V1 migration 支撑 P0 交易事实、可靠事件、标签、审计和后台治理表结构。
- 任务清单可以被拆成小提交或 PR，并以 `docs/plan/06-task-implementation-checklist.md` 作为项目推进主线。
