# 验证计划

## 验收主链路

```text
注册/登录 -> 会场 -> 商品详情 -> 试算 -> 开团/参团
-> 锁单 -> Mock 支付 -> 订单列表 -> 订单详情
-> 退款 -> 管理后台查看订单和任务
```

## 分层验证

### 契约验证

- OpenAPI 可以通过 lint。
- Mock 数据字段和 OpenAPI 一致。
- 前端类型由契约生成或手动保持一致。

### 后端验证

- 单元测试覆盖领域状态机。
- Mapper 测试覆盖关键 SQL。
- 接口测试覆盖成功和失败响应。
- Redis 异常时有降级或补偿路径。

### 前端验证

- 类型检查通过。
- 构建通过。
- 登录过期能跳回登录页。
- 状态展示和后端枚举一致。

### 联调验证

- 用户端完整链路跑通。
- 管理端治理能力跑通。
- 后台写操作产生审计记录。

## 高风险用例

- 未登录访问受保护接口。
- 前端伪造其他用户身份。
- 同一 `clientOrderNo` 重复锁单。
- 并发参团导致队伍满员。
- 重复支付回调。
- 重复退款请求。
- 活动未开始、已结束、已禁用。
- 用户标签未命中。
- 用户限购超限。
- Redis 占位成功但 MySQL 落库失败。
- MySQL 成功但 Redis 释放失败。
- 任务执行失败后重试。
- 管理员权限不足。

## 完成标准

第一版完成时至少满足：

- 后端测试通过。
- 两个前端构建通过。
- 主链路可以稳定演示。
- 高风险用例有明确处理结果。
- 发布说明和回滚说明齐全。
